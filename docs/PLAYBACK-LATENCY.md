# Android 0.1.2 播放排队优化

2026-10-31，用户确认 0.1.1 已无沙沙声和闪断，但体感延迟偏高。
这一轮保持已验证的网络自适应缓冲策略、浮点 PCM、音量与 EQ 算法，
优化 Android AudioTrack 写入排队，并改进接收端状态展示。

## 依据与实现

此前录屏显示 AudioTrack 缓冲为 26936 帧，48 kHz 下相当于约 561 ms。
这是当时显示的缓冲大小，不是已测出的当前排队或端到端延迟。
旧阻塞写入循环会持续填充可用缓冲，因此这层有优化空间。

保留系统分配的容量，通过 `setBufferSizeInFrames` 请求较小的有效大小：

| 模式 | 请求的播放缓冲 | 48 kHz 对应帧数 |
| --- | ---: | ---: |
| 均衡，默认 | 60 ms | 2880 |
| 稳定优先 | 100 ms | 4800 |
| 响应优先 | 30 ms | 1440 |
| 兼容 | 系统原缓冲 | 以设备实际值为准 |

设备可以钳制请求，不能把请求值当作实测延迟。发生输出缺粮后自动扩容，
一次新增事件增长 50% 且至少 10 ms，多次事件翻倍，最大达到系统容量。
本会话不自动缩小已学习的目标。路由首次生效后重新应用目标，换设备按原有
生命周期重建。若设置失败，尝试恢复完整容量并暂停本会话的进一步调节。

渲染块从固定 1024 帧改为约 10 ms，在 48 kHz 为 480 帧，44.1 kHz 为 441 帧。
数组仍一次分配；部分写入循环和阻塞写入保留。诊断与扩容按单调时钟约每
500 ms 检查，避免不同采样率对应不同的固定回调计数。

新增显示有效缓冲大小、系统容量、当前排队估算、输出缺粮和扩容次数。
排队估算仅统计写入成功的双声道样本，并扩展无符号 32 位播放头；
计数异常时显示不可用。估算不参与音频调度，也不覆盖耳机下游延迟。

接口语义参考 Android 官方 AudioTrack 文档：
<https://developer.android.com/reference/android/media/AudioTrack>。

## 验证范围

- 10 项纯 Kotlin/JUnit 测试：设备钳制、扩容上限、路由容量改变、保留学习值、
  错误与异常回退、兼容模式、不同采样率、部分样本写入、播放头符号边界和回绕、异常计数恢复。
- 实际 JVM `-Xcheck:jni`：真实 UDP、静音门控到可听浮点输出、并发诊断/控制、
  单渲染线程约束及生命周期；新增在 8/44.1/48/96/192 kHz 执行 10 ms JNI 填充。
- 原有 41 项 Rust 工作区测试通过，包含成批到达后自适应稳定、漂移及无分配渲染。
- Android 单元测试、APK 构建、lint，以及最终签名、版本和 ZIP 对齐检查见
  [构建记录](../android/BUILD-STATUS.md)。

策略测试使用可控的缓冲适配器，不能证明实体 AudioTrack 接受特定值。
未控制或操作用户手机，未实测新版端到端延迟，也未声称真机已验证无断音。
0.1.1 稳定是用户反馈；0.1.2 的真机效果仍需用户试听。

## 使用建议

只更新 Android APK，Windows 发送端和命令保持原样。先保持网络初始缓冲
150 ms，使用默认“均衡”模式播放相同音乐，观察实际播放缓冲与输出缺粮。
确认稳定后可试“响应优先”。如体验变差，选择“稳定优先”或“兼容”；
切换会重启接收。复制诊断信息可保留两层缓冲及计数，便于后续比较。
