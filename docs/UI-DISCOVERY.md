# 界面与局域网连接

当前界面版本为 0.2.0，PCM 协议仍为 v1。音频的分包、延迟备份、重排、
自适应缓冲、重采样和共享 AudioTrack 播放策略沿用稳定链路。

## Android

- **混音**：开始/停止后台接收、总音量、独立音源、静音/独听、每路 EQ。
- **设备**：局域网设备列表、连接电脑、按 IPv4 地址查找。
- **设置**：输出设备、应用输出格式、设备报告的能力、播放模式、端口、
  缓冲、闪断标记和诊断复制。调整运行中的输出/网络设置会重启接收。
- 跟随系统浅色/深色，悬浮胶囊底栏与滑动选中指示，页面滚动位置在切换时保留。
  点击区域至少 48 dp，导航支持无障碍选中状态，页面编号在 Activity 重建时保留。
- API 33+ 尝试使用 AGSL 边缘折射和真实背景模糊；API 31–32 使用背景模糊；
  老系统使用半透明渐变。着色器创建失败时退回模糊。仅绘制底栏区域，隐藏界面时
  不执行该绘制；视觉效果及不同 GPU 的表现仍需真机确认。

视觉参考是 [KernelSU Manager](https://github.com/tiann/KernelSU/tree/bec9c1347472e26d3d7c46cccb7be801a9c9a6b9/manager)
的 Miuix 界面与 `FloatingBottomBar`。LanMix 的布局、Canvas 绘制及着色器为独立实现，
没有复制 Manager 源文件，也没有引入 Miuix / Compose 依赖。

## Windows

双击 **`lanmix.exe`** 打开发送窗口，无控制台窗口。选择接收设备后点击连接，
或输入 `IP:端口`。默认采集 Windows 系统输出，保留 20 ms 备份。
窗口支持选取其他输出端点；发送时锁定此选项，停止后可切换。

“允许接收端发起连接”默认勾选，仅空闲时生效。关闭后仍能主动连接接收端。
来自接收端的请求不能切换正在使用的目标；关闭窗口会停止采集和发现。
这是纯 Rust 调用 Win32 的界面，没有浏览器、WebView 或另起一个发送子进程。
`lanmix-sender.exe` 保留原有命令行功能；不带参数时也可以打开窗口。
`lanmix-receiver.exe` 是 Rust/egui 桌面混音接收端，也支持设备发现与请求连接。

## 连接方法

1. 电脑打开新版 `lanmix.exe`，手机打开 LanMix。Android 17+ 需允许本地网络访问。
2. 手机在“设备”页面选择电脑并点“连接并接收”。应用先打开接收输出，
   确认就绪后再请求电脑开始发送。
3. 也可先在手机开始接收，再从电脑列表选择手机并连接。
4. 多台电脑分别连接同一接收端后，在混音页面独立调节各路音量和 EQ。

旧命令仍可用：`lanmix-sender.exe send --to 192.168.1.184:46210`。
自动发现要求两端均使用支持发现的新版本；旧版可继续通过 IP 发送。
自动发现失败不影响手动音频发送。程序不会更改系统防火墙；允许 LanMix 在当前
局域网收发 UDP 后再试。访客网络、AP 隔离、VPN 路由或禁止广播的网络可能影响发现。

## 发现协议与生命周期

`lanmix-discovery` 是 Android JNI、Windows 发送端和桌面接收端共享的 Rust 库。
它使用独立线程、独立套接字与有界命令队列，不进入实时 PCM 回调。

| 内容 | 行为 |
|---|---|
| 发现监听 | IPv4 UDP 46211，允许同一主机多个进程监听广播 |
| 音频监听 | 默认 UDP 46210，可在接收端设置 |
| 通告 | `LMXD` / 协议 1 / JSON，最长 1024 字节 |
| 设备信息 | 实例 ID、名称、角色、音频端口、就绪状态、应用版本 |
| 心跳 | 每 2 秒探测本机 IPv4 接口广播；同时向已发现端点发单播心跳 |
| 回复与连接 | 独立动态 UDP 控制端口；用实际收包来源 IP，不接受第三方目标 IP |
| 退出 | 尽力发送 goodbye；7 秒未收到心跳则移除 |
| 连接重试 | 250 ms 间隔共 3 次，同一请求 ID 去重 |
| 容量 | 最多 64 个发现设备；命令、待发请求、入站请求均有上限 |

连接请求仅能由已就绪的接收端发送给允许连接的发送端。音频开始后才会在混音
页面出现实际音源；“已请求连接”不等于已收到音频。此控制面与现有 PCM 协议都
面向可信局域网，尚未提供配对、身份认证或加密。

Android 在页面可见或播放服务存在时维护发现，服务播放期间锁屏不停止发现。
页面隐藏且服务停止后会释放套接字与线程。已发起的连接在服务启动交接时最多
保留 12 秒，通知停止会同时取消待连接请求。发现不在后台启动 Android 播放服务；
需要用户先在接收端启动，或从可见的设备页面发起连接。

## 验证范围

Android 0.2.1 补充：根据 Android 17 真机崩溃日志修复首次启动时系统栏控制器
访问过早的问题。已通过 USB ADB 覆盖安装并确认冷启动成功、进程持续存活，
没有该进程的新崩溃记录；未将此启动检查视为下列全部交互与音频验收。

- Rust 测试检查报文校验、双向发现、重复连接请求、忙碌设备、错误目标、过期与退出。
- 宿主 JVM 使用真实 JNI 和 UDP 检查身份更新、查找、列表、连接请求和释放。
- `python scripts/test_discovery.py --bin-dir dist/windows-x64-0.2.0`
  启动真实 Windows CLI 进程，验证发现、回复与音频端口隔离；不打开界面或播放声音。
- 原有多采样率混音和备份丢包恢复进程检查继续通过。

本轮没有控制用户桌面或手机，也未验证实体 Wi-Fi、玻璃效果、Windows 窗口交互、
Android 点击连接、后台锁屏和蓝牙实际听感。需在安装新版后做这些设备验收。
