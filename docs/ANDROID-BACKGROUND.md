# Android 后台接收与共享播放

1.0.4 开发构建补充：单个支持控制的 Windows 发送端连接后，前台服务通知使用
`Notification.MediaStyle` 显示上一首、播放/暂停、下一首；展开后仍可停止接收。
没有引入 Android MediaSession，也不申请音频焦点。多个设备、额外待连接设备或旧版
发送端不显示媒体按钮；暂停/静音不影响已确认连接。每次操作重新校验目标和会话，
旧通知不能操作新的连接。独立 UDP 控制消息重试时去重，避免一次点击重复切换播放状态。
实际执行采用 Windows 系统媒体键，不承诺选择特定播放器，也不推测远端播放状态。
以下为初次后台播放实现时的历史说明；普通通知的描述不包含本次新增的条件媒体样式。

2026-10-31，Android 0.1.5 / version code 6。Windows 工具继续使用 0.1.4，
PCM 格式、协议 v1、延后备份、DSP、重采样和既有输出缓冲策略均未修改。

## 行为与实现

旧版在启动 AudioTrack 时申请 `AUDIOFOCUS_GAIN`，并在 Activity.onStop
停止接收。这是当前代码中与“和其他应用同时出声、后台继续”直接冲突的两条路径。
本轮移除焦点请求与焦点丢失停止逻辑，将播放拥有权移到 `ReceiverService`。

音频路径为 UDP → Rust 重排/混音/EQ → 浮点 AudioTrack → 系统共享输出。
这是直接 PCM，不经过 MediaPlayer、ExoPlayer，也不申请独占设备或冒用通话/通知
用途。保留 `USAGE_MEDIA` / `CONTENT_TYPE_MUSIC`，不修改系统音乐音量、
AudioManager.mode、扬声器开关、蓝牙 SCO 路由或其他应用的媒体会话。
正常用途为用户明确选择的多应用并行声音；没有用错误的声音类别绕过系统策略。

- 用户在前台页面点击开始，启动 `mediaPlayback` 前台服务，先展示静默通知，
  再异步打开音频和 UDP。声明 FOREGROUND_SERVICE / FOREGROUND_SERVICE_MEDIA_PLAYBACK。
- 按 Home、切换应用、锁屏、页面旋转/重建或移除 Activity 任务不主动停止。
  关闭接收使用页面按钮或通知的停止动作，等待写入线程退出后撤销前台状态。
- Android 13+ 首次启动时申请通知权限，拒绝仍可启动服务，页面解释停止入口。
  Android 17+ 的局域网运行时权限依旧单独申请，未授予不能开始接收。
- 服务持有带超时的部分 CPU 唤醒锁：每次最多两分钟，每分钟续期；停止、失败
  和销毁释放。屏幕可自然休眠。没有申请电池优化白名单、Wi-Fi 独占/多播锁，
  不自动开机启动、不在进程被终止后自行恢复播放。
- 通知是普通服务通知，有返回页面和停止入口，无 MediaStyle/MediaSession，
  不注册媒体按键处理。播放停止时清理通知。
- 来源绑定、初始静音解除和保存的独立音量/EQ 都在服务轮询中执行，页面隐藏后
  新电脑接入同样有声。轮询不会反复覆盖正在使用的滑块设置。
- 应用进程持有混音设置和最近 64 条诊断历史，页面退出/重建后重新观察同一状态，
  不重建正在播放的流。新音源、缺包和输出异常在后台也会记录。
- 输出设备移除由服务处理，页面只刷新列表。同采样率路由仍保持现有策略，
  自动采样率变化仍需要重建。进程级串行控制器负责清理旧引擎后再打开新引擎；
  旧写入线程仍存活时拒绝替换，防止跨服务实例争用同一 JNI 接收器。

## 共播边界

不抢音频焦点可以避免 LanMix 主动要求其他普通播放器暂停/降低音量，
但不能承诺所有手机、所有应用、所有外部音频路由都同时播放。
通话、独占/直通播放器、厂商音频策略、后台限制和系统强制结束仍可能中断或静音。
前台服务类型的名称 `mediaPlayback` 是 Android 对后台音频任务的分类，
不代表引入播放器框架；更换成 Oboe/AAudio 也不能解除这些系统级限制。
长期后台接收比前台即停更耗电，需要用户明确结束不用的会话。

## 验证范围

22 项 Kotlin/JUnit 测试通过，新增 4 项直接验证服务使用的来源控制门控：
无页面接入两个来源分别应用保存的增益、重复轮询不覆盖实时控制、槽位换来源
不会继承旧设置、接收重建后已知来源重新应用、无效槽位不能操作控制，
以及 JNI 控制暂时失败后重试，避免已绑定来源永远保持初始静音。
Android 构建/lint、APK 签名/对齐和宿主 JNI 检查结果见构建记录。
原生 Rust 和 JNI 库未改动，使用此前已验证的 ARM64/ARMv7 构建。

没有操作用户手机、没有进行 Android 多应用/锁屏/通知真机实验。
以下项目是安装后的验收步骤，不能把单元测试通过当作这些项目已经通过：

1. 先播放手机音乐或视频，再启动 LanMix，确认原应用继续播放，两路均有声。
2. 反过来先启动 LanMix，再开音乐/视频，确认 LanMix 继续有声；滑块只改变
   LanMix 音源音量，不改变其他应用音量。
3. 接收时按 Home、锁屏至少五分钟，再打开页面；确认来源、音量/EQ 和缺帧
   累计保留，历史没有因页面隐藏而出现新的接收会话。
4. 在页面隐藏时让另一台电脑开始发送，确认新来源可听到，返回页面可调节。
5. 旋转/重开页面或从最近任务移除页面，确认服务仍在；通过通知停止后确认
   声音停止、通知消失，回到页面为已停止。
6. 拒绝通知权限，确认仍可在页面启动和停止；设备拔插或路由变化后检查实际
   输出报告。若通话或省电策略中断，保留诊断并记录手机型号和动作顺序。

## 官方依据

Android 官方音频焦点文档说明多个应用可经系统混音同时输出，也建议普通媒体
应用遵守焦点管理。本工具按用户明确要求实现共享播放，界面说明共播边界。
前台服务类型文档列明 mediaPlayback 用于后台音视频，没有额外运行时前提；
通知权限文档说明拒绝通知不阻止前台服务，但服务仍须提供通知。
